# MeridianEd Documentation Style Guide (READ FIRST)

This file defines the shared conventions for every file in `school-system/docs/`.
Follow it exactly so all deliverables read as one coherent package.

## 1. Product identity

- Product name: **MeridianEd** (descriptor: *Cloud-Based School Management Ecosystem*).
- Codename used internally: **MSP** (Meridian School Platform). One line in each doc:
  > MeridianEd is a placeholder brand — the name is rebrandable at any time.
- One sentence pitch (use variants of this, never contradict it):
  > MeridianEd is a secure, cloud-native, AI-powered, mobile-first school management
  > ecosystem that centralizes academic, administrative, financial, HR, health,
  > guidance, research, and operational data for elementary schools, junior/senior
  > high schools, colleges, universities, school divisions, and regional offices.

## 2. Context (must stay consistent)

- Primary market: Philippine K-12 (DepEd). Must reference: LRN (Learner Reference
  Number), School Forms SF1–SF6, K-12 curriculum, SHS tracks (Academic, TVL, Sports,
  Arts & Design), Phil-IRI, ARAL, RMA (Rapid Mathematics Assessment), NC II/TESDA,
  Work Immersion, BERF (Basic Education Research Fund), Division/Regional offices,
  RA 10173 (Philippine Data Privacy Act).
- Must also scale to colleges and universities (the platform is level-agnostic).
- Primary cloud: **Google Cloud Platform (GCP)**. Note AWS/Azure equivalents in one
  line where natural (e.g. `Cloud SQL → RDS/Azure SQL`). Never write whole sections
  for all three clouds.
- Primary timezone: Asia/Manila (UTC+8). Currency: PHP.

## 3. Production target stack (stated as the "target architecture")

| Layer | Choice |
|---|---|
| Web frontend | Next.js 15 + React 19 + TypeScript |
| Mobile | Flutter 3 (Android 9+, iOS, tablet, Chromebook) |
| Backend | Node.js 22 + NestJS + TypeScript |
| API style | REST (JSON) + GraphQL gateway later |
| Database | PostgreSQL 16 (Cloud SQL), Redis 7 cache |
| Auth | Keycloak (OAuth2/OIDC) + JWT; Google/MS/DepEd SSO |
| Cloud | GCP: Cloud Run/GKE, Cloud Storage, Cloud CDN, Cloud Load Balancing |
| DevOps | Docker, Kubernetes, Terraform, GitHub Actions |
| Observability | Prometheus, Grafana, ELK/Cloud Logging |

> **MVP note** (must appear in docs where relevant): the runnable MVP in this repo
> uses the same concepts at a smaller scale: Express (Node 22) + PostgreSQL with a
> `node:sqlite` local fallback, React 19 + Vite web portal, and a Capacitor 8 Android
> wrapper. Production features described in docs may exceed what the MVP implements;
> every doc must clearly mark what is "vision" vs "MVP".

## 4. SLOs / defaults (use these numbers everywhere)

- Availability target: **99.9%** (multi-zone, no single point of failure).
- RPO: **≤ 15 minutes** (continuous WAL archiving + nightly snapshots).
- RTO: **≤ 4 hours** (region failover); RTO ≤ 15 min for database HA.
- Password policy: ≥ 12 chars, complexity, 90-day expiry, 5 failed attempts → 15-min lockout.
- Sessions: JWT access token 15 min + refresh token 14 days (rotation, revocation).
- Audit log: immutable, append-only, retained 7 years (DepEd/DPA).

## 5. Roles (single source of truth)

`super_admin`, `region_admin`, `division_admin`, `school_admin`, `principal`,
`assistant_principal`, `registrar`, `teacher`, `guidance`, `nurse`, `librarian`,
`cashier`, `accounting`, `hr`, `property_custodian`, `ict`, `security`, `student`, `parent`.

Hierarchy: region → division → school → (section). Access is scoped to the
user's tree node (school/division/region) via RBAC + row-level tenant scoping.

## 6. Core modules list (use consistently)

Dashboard, Student Information System, Teacher Management, Academic Management
(curriculum, subjects, sections, scheduling, DLL/lesson plans, assessments, grades,
report cards), Attendance, Finance, Library, Clinic, Guidance, Property Management,
Research, Communication, AI Features, Reports (SF1–SF6 + operational), System Admin.

## 7. File format rules

- Filename: `NN-slug.md` where NN is the deliverable number (already fixed in the task list).
- Start with `# <Title>` — the title from the deliverable list, then one intro paragraph.
- Use `##` for sections, `###` for subsections. No H3 deep nesting beyond one level if avoidable.
- Tables for anything tabular. Mermaid for diagrams (```mermaid). ASCII art only if mermaid is unsuitable (e.g. wireframes — ASCII is fine there).
- Use RFC 2119 keywords (MUST, SHOULD, MAY) in requirements docs.
- Use PHP (₱) for money, LRN format `XXXXXXXXXXXX` (12 digits) where relevant.
- End every file with:
  `---`
  `*MeridianEd — Cloud-Based School Management Ecosystem — Deliverable N of 30.*`
- No emojis. Professional, concise, concrete. Avoid filler ("robust", "state-of-the-art" unless earned).

## 8. What NOT to do

- Do not invent contradictions with this guide (roles, stack, SLOs, numbers).
- Do not write content for another agent's deliverable files (files are exclusive per agent).
- Do not write code in docs beyond tiny snippets/examples; keep examples minimal.
- Do not exceed ~600 lines per file; quality over quantity.
